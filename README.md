# نظام إدارة حلقات تحفيظ القرآن الكريم

نظام ويب متكامل لإدارة حلقات تحفيظ القرآن في المسجد: الطلاب، المعلمون، الحلقات، الحضور، التسميع اليومي،
الاختبارات المتسلسلة، طلبات النقل والإيقاف، بوابة أولياء الأمور، الدعم الفني، الإشعارات والمحادثات الفورية.

الواجهة عربية بالكامل باتجاه RTL ومتجاوبة مع الجوال والأجهزة اللوحية وسطح المكتب.

## التقنيات

### الخادم (Backend)

| التقنية | الاستخدام |
|---|---|
| NestJS 10 + TypeScript | إطار العمل وبنية الوحدات |
| Prisma 5 | ORM والهجرات (Migrations) |

| class-validator | التحقق من المدخلات |
| bcryptjs + helmet | تشفير كلمات المرور وحماية الترويسات |

### الواجهة (Frontend)

| التقنية | الاستخدام |
|---|---|
| React 18 + TypeScript | واجهة المستخدم |
| Vite 5 | أداة البناء وخادم التطوير |
| React Router 6 | التنقل وحماية المسارات |
| TanStack Query 5 | جلب البيانات والتخزين المؤقت |
| Zustand | حالة المصادقة |
| Axios | عميل HTTP مع تجديد الرمز تلقائياً |

| Recharts | الرسوم البيانية |

> **ملاحظة عن قاعدة البيانات:** يستخدم المشروع **PostgreSQL** لأنه المتوفر والمثبّت على بيئة التطوير الحالية
> (لم يكن MySQL مثبتاً). للتحويل إلى MySQL: غيّر `provider` في `backend/prisma/schema.prisma` إلى `"mysql"`،
> واستبدل حقول `String[]` (مثل `Circle.scheduleDays`) بحقل نصي أو جدول منفصل لأن MySQL لا يدعم المصفوفات،
> ثم أعد توليد الهجرات.

## التثبيت السريع

من مجلد المشروع الرئيسي:

```bash
# 1) أنشئ قاعدة البيانات (مرة واحدة)
psql -U postgres -c "CREATE DATABASE quran_circles;"

# 2) اضبط بيانات الاتصال
#    انسخ backend/.env.example إلى backend/.env وعدّل DATABASE_URL

# 3) تثبيت الحزم + الهجرات + البيانات التجريبية
npm run setup
```

ثم شغّل الخادمين في نافذتي طرفية منفصلتين:

```bash
npm run dev:backend    # http://localhost:3000
npm run dev:frontend   # http://localhost:5173
```

افتح المتصفح على **http://localhost:5173** وسجّل الدخول بالبريد `admin@alnoor-quran.sa` وكلمة المرور `Pass@1234`.

## التثبيت خطوة بخطوة

### 1. قاعدة البيانات

```bash
psql -U postgres -c "CREATE DATABASE quran_circles;"
```

على ويندوز إذا لم يكن `psql` في مسار النظام:

```powershell
& "C:\Program Files\PostgreSQL\14\bin\psql.exe" -U postgres -c "CREATE DATABASE quran_circles;"
```

### 2. الخادم

```bash
cd backend
cp .env.example .env      # على ويندوز: copy .env.example .env
```

عدّل `DATABASE_URL` في `backend/.env` ليطابق بيانات اتصالك:

```env
DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/quran_circles?schema=public"
```

ثم:

```bash
npm install
npm run prisma:migrate    # ينشئ الجداول
npm run seed              # يعبّئ البيانات التجريبية
npm run dev               # http://localhost:3000
```

### 3. الواجهة

في نافذة طرفية جديدة:

```bash
cd frontend
npm install
npm run dev               # http://localhost:5173
```

خادم التطوير يمرّر `‎/api` و `‎/uploads` و `‎/socket.io` تلقائياً إلى الخادم على المنفذ 3000،
لذلك لا حاجة لضبط CORS أثناء التطوير.

## الحسابات التجريبية

كلمة المرور موحّدة لجميع الحسابات: **`Pass@1234`**

تسجيل الدخول يتم **بالبريد الإلكتروني**؛ جميع العناوين التجريبية على النطاق `@alnoor-quran.sa`.

| الدور | البريد الإلكتروني | ما يراه |
|---|---|---|
| مدير عام | `admin@alnoor-quran.sa` | كل شيء: المستخدمون، الحلقات، الطلاب، اعتماد الطلبات، الإعدادات |
| مشرف | `supervisor1@…` / `supervisor2@…` | الحلقات المسندة إليه فقط وطلابها ومعلموها |
| معلم | `teacher1@…` … `teacher7@…` | حلقاته وطلابه، الحضور، التسميع، طلبات النقل/الإيقاف/الاختبار |
| لجنة اختبارات | `committee1@…` / `committee2@…` | قائمة الانتظار، الجدولة، رصد النتائج |
| ولي أمر | `parent1@…` … `parent12@…` | أبناؤه فقط (قراءة فقط) |
| دعم فني | `support@alnoor-quran.sa` | تذاكر الدعم والرد عليها |

أي حساب ينشئه المدير لاحقاً يبدأ بكلمة مرور تعيّنها الإدارة، ويُوجَّه صاحبه عند أول دخول إلى صفحة
**الملف الشخصي** لتغييرها قبل استخدام أي شاشة أخرى.

البيانات التجريبية تشمل: ٦ حلقات، ٧ معلمين، ٦٥ طالباً، ١٢ ولي أمر، أكثر من ١١٠٠ سجل حضور، نحو ٤٠٠ سجل تسميع،
اختبارات مكتملة وناجحة وراسبة، قائمة انتظار اختبارات، طلبات نقل وإيقاف معلّقة ومعتمدة، تذاكر دعم، ومحادثات فردية وجماعية.

لإعادة تعبئة البيانات من الصفر:

```bash
npm run seed          # يمسح الجداول ويعيد التعبئة
npm run db:reset      # يحذف قاعدة البيانات ويعيد بناءها بالكامل
```

## الأدوار والصلاحيات

النظام يطبّق مستويين من الحماية:

1. **حماية على مستوى الدور** — `RolesGuard` عام يمنع الوصول لنقاط النهاية غير المسموحة للدور.
2. **حماية على مستوى المورد** — `AccessControlService` يحدد *أي* الحلقات والطلاب يستطيع هذا المستخدم بالذات رؤيتهم أو تعديلهم.

| الدور | النطاق |
|---|---|
| **مدير عام** | وصول كامل لكل الوحدات، واعتماد جميع الطلبات |
| **مشرف** | الحلقات المسندة إليه فقط: طلابها، معلموها، حضورها، تسميعها، اختباراتها |
| **معلم** | حلقاته فقط (أساسي أو مساعد). يسجّل الحضور والتسميع والتقييم، ويقدّم طلبات النقل والإيقاف والاختبار |
| **لجنة اختبارات** | قراءة بيانات الطلاب لأغراض الاختبار + جدولة الاختبارات ورصد النتائج |
| **ولي أمر** | أبناؤه فقط، **قراءة فقط** |
| **دعم فني** | تذاكر الدعم فقط، ولا يصل لبيانات الطلاب |

**أمثلة مطبّقة فعلياً في الخادم:**

- المعلم لا يستطيع فتح ملف طالب خارج حلقاته → `403`
- ولي الأمر لا يستطيع رؤية طالب آخر → `403`
- المعلم يستطيع تعديل بيانات التواصل ومستوى الحفظ فقط، ومحاولة تعديل الاسم أو الهوية أو الحلقة تُرفض → `403`
- المشرف لا يستطيع تعيين مشرف أو معلم أساسي (صلاحية إدارية) → `400`
- إيقاف حساب أو حذفه يُلغي جميع جلساته فوراً

> الواجهة تُخفي ما لا يملكه المستخدم، لكن **القرار النهائي دائماً في الخادم** — إخفاء الزر ليس حماية.

## ملاحظات الواجهة

### القائمة الجانبية القابلة للطي

على الشاشات الكبيرة يمكن طي القائمة الجانبية إلى شريط أيقونات (٨٠ بكسل بدلاً من ٢٨٨) بالضغط على زر
السهم في الشريط العلوي. عند الطي تظهر تلميحات عند مرور المؤشر، وتتحول عدادات الإشعارات إلى نقاط صغيرة.
الحالة تُحفظ في `localStorage` تحت المفتاح `qc.sidebarCollapsed` فتبقى بين الجلسات.
على الجوال لا ينطبق الطي — القائمة تظهر كدرج منسدل كامل.

### الأرقام والتواريخ داخل نص عربي (`.numeric`)

النصوص المختلطة (أرقام لاتينية داخل فقرة عربية) تنعكس بصرياً إذا تُركت لخوارزمية الاتجاه الافتراضية،
فيظهر التاريخ `2026/08/14` على شكل `142026/08/`. لذلك يوفّر النظام صنف `.numeric`:

```css
.numeric {
  font-variant-numeric: tabular-nums;
  unicode-bidi: plaintext;   /* يحدد الاتجاه من أول حرف قوي في المحتوى */
  white-space: nowrap;
}
```

استخدمه على أي تاريخ أو رقم أو رمز أو رقم جوال. **لا تُضِف إليه `display` أبداً** — الصنف يُطبَّق على
عناصر `<td>`، وأي تغيير في `display` يُخرج الخلية من تخطيط الجدول ويُفقد محاذاة الأعمدة.

### الحضور: إرسال واحد لكل يوم

بعد حفظ كشف حضور حلقة في يوم معيّن يختفي زر الحفظ وتتحوّل الحالات إلى شارات للعرض فقط، ويرفض الخادم
أي إرسال ثانٍ لنفس (الحلقة، التاريخ) برسالة واضحة. يستثنى من ذلك **المدير العام والمشرف** فقط، ليبقى
تصحيح الخطأ ممكناً دون فتح الباب للتسجيل المزدوج. الكشف يعرض من سجّله ومتى.

الحالات ثلاث لا رابع لها: **حاضر**، **غياب بعذر** (مع حقل السبب)، **غياب بدون عذر**. نسبة الحضور
تُحتسب من الحاضرين فقط.

### الجداول

- الخلايا لا تلتف افتراضياً (`white-space: nowrap`) ليبقى ارتفاع الصفوف متساوياً.
- للأعمدة النصية الطويلة (مثل «السبب») أضف `whitespace-normal` على الخلية.
- `.table` لها `min-width: 44rem` فتُمرَّر أفقياً داخل `.table-wrap` على الشاشات الضيقة بدل ضغط الأعمدة.
- المحاذاة موروثة من `.table`، لذا تبقى أدوات مثل `text-center` على خلية بعينها فعّالة.

## قاعدة البيانات

النموذج يغطي ٢٣ جدولاً. أهم العلاقات:

- **`User`** هو الحساب. المعلم وولي الأمر لهما ملف إضافي (`TeacherProfile` / `ParentProfile`) بعلاقة ١:١.
- **`CircleTeacher`** يربط المعلم بالحلقة بدور (`PRIMARY` / `ASSISTANT`). الحقل `endedAt = null` يعني الإسناد الحالي،
  وبقية السجلات تشكّل **تاريخ الإسناد الكامل** — لا يُحذف شيء عند النقل.
- **`CircleMembership`** يفعل الشيء نفسه للطلاب: كل انتقال بين الحلقات يُغلق سجلاً ويفتح آخر.
- **`StudentEvaluation`** يحفظ تاريخ كل تغيير في التقييم اليدوي، بينما يحتفظ `Student.evaluation` بالقيمة الحالية.
- **`Attendance`** عليه قيد فريد `(studentId, date)` — إعادة تسجيل نفس اليوم تُحدّث السجل ولا تكرره.
  الحالات ثلاث فقط: `PRESENT` (حاضر) و`EXCUSED` (غياب بعذر) و`ABSENT` (غياب بدون عذر)، والحقل `note`
  يحمل سبب العذر ولا يُحفظ إلا مع `EXCUSED`.
- **`Recitation`** للتسميع اليومي: تقييم عام (`evaluation`) وملاحظات فقط — بلا درجة رقمية وبلا عدد أخطاء.
- **`Exam`** للاختبار الرسمي: `score` من 100 وهو ما يحدّد النجاح، و`mistakes` **اختياري**، و`notes` للملاحظات.
- **`SuspensionRequest`** و **`TransferRequest`** تحفظان الطلب وقراره ومنفّذه، مع الاحتفاظ بالسجل بعد التنفيذ.
- **الحذف الناعم** (`deletedAt`) مطبّق على المستخدمين والمعلمين وأولياء الأمور والطلاب والحلقات والتسميع والتذاكر والملاحظات.

**الفهارس:** أُضيفت فهارس على كل حقول التصفية والفرز المستخدمة فعلياً — حالة الطالب، الحلقة، التاريخ،
حالة الطلب، مالك الإشعار، ومحادثة الرسالة — لتظل الاستعلامات سريعة مع آلاف السجلات.

لاستعراض البيانات بصرياً:

```bash
cd backend && npm run prisma:studio
```

## نظام الاختبارات المتسلسل

المسار مبني على **٣٠ مقرراً** (`ExamSection`) مرتّبة بالحقل `order`، ابتداءً من **الجزء ٣٠** (جزء عمّ) تنازلاً
إلى **الجزء ١** — وهو الترتيب المتّبع في حلقات التحفيظ.

**القاعدة الأساسية:** لا يُقبل تقديم طالب لمقرر إلزامي قبل اجتياز كل المقررات الإلزامية التي تسبقه في الترتيب.

```
طلب الاختبار (معلم)
   ↓  التحقق من الأهلية: هل اجتاز كل ما قبله؟
قائمة الانتظار PENDING
   ↓  اللجنة تجدول (يُعاد التحقق من الأهلية مجدداً)
اختبار مجدول SCHEDULED  →  إشعار للمعلم وولي الأمر والممتحن
   ↓  رصد النتيجة
COMPLETED  →  PASSED إذا كانت الدرجة ≥ درجة النجاح، وإلا FAILED
              (الدرجة من 100 إلزامية، وعدد الأخطاء اختياري)
   ↓  عند النجاح: تُحدَّث الأجزاء المحفوظة للطالب ويُفتح المقرر التالي
```

- التحقق يتم **مرتين**: عند تقديم الطلب وعند الجدولة (قد تتغير الحالة بينهما).
- الرسوب لا يُغلق المسار: يمكن للمعلم إعادة تقديم الطلب لنفس المقرر.
- **لا يُقبل طلب جديد ما دام هناك طلب قائم** (PENDING أو SCHEDULED) للطالب. في هذه الحالة تعرض الشاشة
  اسم المقرر المنتظر صراحةً (`بانتظار البتّ في طلب «الجزء ٢٩»`) بدلاً من رسالة عامة، فيعرف المعلم أن
  المطلوب هو بتّ اللجنة لا اجتياز مقرر آخر.
- شاشة الطالب تعرض المسار كاملاً بأربع حالات: **مجتاز** (أخضر)، **طلب قائم** (أزرق)، **متاح الآن** (ذهبي)،
  **مغلق حتى اجتياز ما قبله** (رمادي).
- لتغيير المنهج: عدّل `EXAM_SECTIONS` في `backend/src/common/quran.ts` وفي `backend/prisma/seed.ts`،
  أو أضف مقررات من واجهة الإدارة عبر `POST /api/exams/sections`.

## الإشعارات والمحادثات الفورية

Socket.IO مستخدم **حصراً** للمحادثات والإشعارات اللحظية. كل ما عدا ذلك يمرّ عبر REST.

- **المسار:** `/socket.io` — **النطاق (namespace):** `/realtime`
- **المصادقة:** يُرسل رمز الوصول في `auth.token` أثناء المصافحة (handshake)، ويُرفض الاتصال إذا كان الرمز غير صالح أو الحساب موقوفاً.
- **الغرف:** `user:<id>` للإشعارات الشخصية، `conversation:<id>` للمحادثات، `role:<ROLE>` للبث حسب الدور.

| الحدث | الاتجاه | الوصف |
|---|---|---|
| `notification:new` | خادم ← عميل | إشعار جديد + عدد غير المقروء |
| `chat:message` | خادم ← عميل | رسالة جديدة في محادثة مفتوحة |
| `chat:inbox` | خادم ← عميل | تنبيه لعضو خارج المحادثة المفتوحة |
| `chat:read` / `chat:message-deleted` | خادم ← عميل | تحديث حالة القراءة / حذف رسالة |
| `presence:update` | خادم ← عميل | اتصال/انقطاع مستخدم |
| `typing` | ثنائي الاتجاه | مؤشر «يكتب الآن» |
| `conversation:join` / `conversation:leave` | عميل ← خادم | الانضمام لغرفة محادثة (يُتحقق من العضوية) |

**الإشعارات تُحفظ في قاعدة البيانات** مع حالة مقروء/غير مقروء، فلا تضيع إذا كان المستخدم غير متصل.
وإذا كان عضو المحادثة غير متصل يُنشأ له إشعار دائم بالرسالة.

### إدارة المحادثات والمجموعات

| الإجراء | من يملكه |
|---|---|
| تعديل رسالة | كاتب الرسالة فقط، وتُوسم «مُعدَّلة» |
| حذف رسالة | كاتبها، أو مشرف المجموعة (إشراف)، أو المدير العام |
| عرض الأعضاء | أي عضو في المجموعة |
| إضافة أعضاء | مشرف المجموعة |
| ترقية عضو / إزالة الإشراف | مشرف المجموعة |
| إزالة عضو | مشرف المجموعة |
| تعديل الاسم والوصف | مشرف المجموعة |
| **الإرسال للمشرفين فقط** | مشرف المجموعة — يبقى الأعضاء قادرين على القراءة |
| **إغلاق المجموعة** | مشرف المجموعة — إيقاف الرسائل نهائياً مع حفظ السجل |
| مغادرة المجموعة | أي عضو (لا تنطبق على المحادثات الفردية) |

- مُنشئ المجموعة يصبح مشرفها تلقائياً، ولا يمكن أن تبقى المجموعة دون مشرف واحد على الأقل.
- تُرجع الواجهة الخلفية الحقول `isAdmin` و `canPost` و `isClosed` و `adminOnly` مع كل محادثة،
  فتُخفي الواجهة الأمامية محرّر الرسائل وأزرار الإدارة بناءً عليها بدل إظهار أزرار تفشل عند الضغط.
- قيود المجموعات لا تنطبق على المحادثات الفردية؛ محاولة تطبيقها عليها تُرفض بـ `400`.

الأحداث التي تولّد إشعارات: قرارات النقل والإيقاف، جدولة الاختبارات ونتائجها، طلبات الاختبار الجديدة،
ردود الدعم الفني، رسائل المحادثات، تسجيل الغياب (لولي الأمر)، وإسناد الحلقات.

## النشر للإنتاج

### 1. تجهيز البيئة

```bash
# على الخادم
export NODE_ENV=production
export DATABASE_URL="postgresql://user:strong_password@db-host:5432/quran_circles?schema=public"
export JWT_ACCESS_SECRET="$(openssl rand -hex 32)"
export JWT_REFRESH_SECRET="$(openssl rand -hex 32)"
export CORS_ORIGINS="https://your-domain.com"
export PORT=3000
```

> **مهم:** لا تستخدم القيم الافتراضية لمفاتيح JWT في الإنتاج إطلاقاً، ولا ترفع ملف `.env` إلى المستودع.

### 2. بناء وتشغيل الخادم

```bash
cd backend
npm ci --omit=dev
npx prisma generate
npx prisma migrate deploy      # يطبّق الهجرات دون إنشاء هجرات جديدة
npm run build
node dist/main.js
```

للتشغيل الدائم عبر PM2:

```bash
npm install -g pm2
pm2 start dist/main.js --name quran-api --env production
pm2 save && pm2 startup
```

### 3. بناء الواجهة

```bash
cd frontend
npm ci
npm run build                  # الناتج في frontend/dist
```

ارفع محتويات `frontend/dist` إلى أي خادم ملفات ثابتة (Nginx، Apache، Netlify، Vercel…).

### 4. مثال إعداد Nginx

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # ملفات الواجهة الثابتة
    root /var/www/quran-circles/dist;
    index index.html;

    # مسارات React Router تُعاد إلى index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # واجهة API
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # الملفات المرفوعة (الشعار)
    location /uploads/ {
        proxy_pass http://127.0.0.1:3000;
    }

    # Socket.IO — يحتاج ترقية الاتصال إلى WebSocket
    location /socket.io/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 86400;
    }
}
```

### 5. قائمة تحقق قبل الإطلاق

- [ ] مفاتيح `JWT_ACCESS_SECRET` و `JWT_REFRESH_SECRET` عشوائية وقوية
- [ ] `CORS_ORIGINS` يحتوي نطاق الإنتاج فقط
- [ ] كلمة مرور قاعدة البيانات قوية والوصول إليها محصور بالخادم
- [ ] HTTPS مفعّل (Let's Encrypt أو شهادة أخرى)
- [ ] **تغيير كلمة مرور حساب `admin` فوراً بعد أول دخول**
- [ ] حذف أو تعطيل الحسابات التجريبية
- [ ] `npx prisma migrate deploy` بدلاً من `migrate dev`
- [ ] نسخ احتياطي دوري لقاعدة البيانات (`pg_dump`)
- [ ] مجلد `uploads` قابل للكتابة ومشمول بالنسخ الاحتياطي

## استكشاف الأخطاء

**`Can't reach database server` عند تشغيل الهجرات**
تأكد أن خدمة PostgreSQL تعمل وأن `DATABASE_URL` صحيح:
```bash
pg_isready -h localhost -p 5432
```

**`password authentication failed for user "postgres"`**
كلمة المرور في `DATABASE_URL` غير مطابقة. عدّل `backend/.env`.

**الواجهة تعمل لكن كل الطلبات ترجع `401`**
انتهت صلاحية الجلسة. سجّل الخروج والدخول مجدداً. إذا تكرر ذلك بعد إعادة تشغيل الخادم فالسبب أن
`JWT_ACCESS_SECRET` تغيّر — الرموز القديمة لم تعد صالحة، وهذا سلوك صحيح.

**`الحلقة مكتملة العدد` عند نقل طالب**
سعة الحلقة الهدف ممتلئة. ارفع `capacity` من صفحة الحلقة أو اختر حلقة أخرى.

**المحادثات لا تصل فورياً**
تحقق من وصول `/socket.io` إلى الخادم. خلف وسيط (proxy) يجب تمرير ترويسات `Upgrade` و `Connection`
كما في مثال Nginx أعلاه. النظام يعمل بدون WebSocket لكن الرسائل ستتأخر حتى التحديث التالي.

**`لا يمكن التقدم لاختبار "الجزء ٢٩" قبل اجتياز "الجزء ٣٠"`**
هذا ليس خطأ — إنه تطبيق قاعدة التسلسل الإلزامي. راجع [نظام الاختبارات المتسلسل](#نظام-الاختبارات-المتسلسل).

**`لا يمكن حذف الحلقة لوجود طلاب مسجلين بها`**
انقل الطلاب إلى حلقة أخرى أولاً، ثم احذف الحلقة.

**منفذ ٣٠٠٠ أو ٥١٧٣ مشغول**
غيّر `PORT` في `backend/.env`، أو `server.port` في `frontend/vite.config.ts`.
