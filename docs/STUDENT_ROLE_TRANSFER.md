# نقل وظائف ولي الأمر إلى الطالب

أزيلت وحدة ولي الأمر وصفحاته ودوره من الواجهة، وأصبحت التنبيهات الدراسية والاستدعاءات والشهادات والتسجيل في الدورات ونتائج الاختبارات موجهة لحساب الطالب. تتضمن بوابته التقييمات والملاحظات العامة والاستدعاءات والتحضير وروابط الرسائل والتقارير. أصبح رفع الصورة متاحًا للطالب نفسه، مع التحقق من ملكية الملف على الخادم. حُجبت الملاحظات الداخلية عنه، وأُوقف فتح حساب ولي أمر محفوظ دون اتصال.

تبقى قيمة `PARENT` في تعداد PostgreSQL، وجدول `parent_profiles` وعلاقة `students.parentId` للأرشفة والترحيل فقط. لا تمنح هذه القيمة أي صلاحية تشغيلية، ولا يمكن إنشاء حساب بها أو إعادة تفعيله أو تعديله من إدارة المستخدمين. لا توجد وحدة API لولي الأمر. تبقى بيانات جهة اتصال الطوارئ حقولًا داخل ملف الطالب، دون حساب مستقل أو صلاحيات.

## التحقق المنفذ وحدوده

- نجح 119 اختبارًا محددًا للخادم والواجهة والترحيل، وفحص TypeScript للخادم والواجهة وبيانات التهيئة، وبناء الواجهة للإنتاج. ظهرت تنبيهات Vite عن تقسيم الحزم وحجمها دون أخطاء بناء.
- اختبارات الخادم تغطي ربط الطالب بالهوية الموثقة، ورفض الوصول إلى طالب آخر، وحجب الملاحظات الخاصة، والاستدعاء دون وجود ولي أمر، ورفض الدور في DTO الحسابات والإعلانات.
- اختبارات أداة الترحيل تستخدم معاملات محاكاة وملفات مشفرة فعلية: الفحص دون كتابة، منع الربط الملتبس، فك النسخة الاحتياطية، الحفاظ على المصادر والتواريخ وحالة القراءة، إعادة التشغيل دون تكرار، إنشاء حساب مستقل، ونقل تذاكر الدعم والتراجع عند الفشل.
- اختبارات الواجهة تغطي إيقاف الدخول المحلي لحساب ولي الأمر، وسياسة مسارات الطالب، والمزامنة والتحميل المسبق.
- **لم تُنفذ عملية ترحيل على قاعدة فعلية.** لا توجد `DATABASE_URL` أو `DIRECT_URL` مهيأة في الجلسة. اختبار فك النسخة التجريبية لا يغني عن تجربة استعادة نسخة قاعدة الإنتاج في بيئة معزولة.
- النموذج الحالي للحضور يستخدم `PRESENT` و`ABSENT` و`EXCUSED`؛ لا يوجد فيه حقل مستقل للتأخير. تُعرض الملاحظات المسجلة على الحضور كما هي، ولا تُنشأ معلومات تأخير غير موجودة.

## الفحص والترحيل

من مجلد `backend`، بعد تهيئة الاتصال بالقاعدة المقصودة:

```powershell
node scripts/transfer-parent-data.mjs --mapping transfer-mapping.json
```

الوضع الافتراضي يفحص الربط دون تعديل. لا يستنتج الطالب من الاسم أو الهاتف. يُستخدم `studentId` أو رابط الطالب في الإشعار، أو الربط الصريح، أو الطالب الوحيد المرتبط بالحساب. وجود أكثر من ابن دون مرجع واضح يوقف العملية كلها. تتطلب تذاكر تغيير كلمة المرور وحذف الحساب ربطًا صريحًا حتى لو كان هناك ابن واحد؛ يجب التأكد من ملاءمة محتواها للطالب قبل الربط. المحادثة الواحدة تُنقل إلى طالب واحد؛ لا تُمنح محادثة تشمل بيانات أبناء مختلفين لأحدهم قبل فصل المحتوى بإجراء مراجع.

شكل ملف الربط (المفاتيح هي المعرفات الأصلية، والقيم معرفات الطلاب المرتبطين بولي الأمر نفسه):

```json
{
  "notifications": { "notification-id": "student-id" },
  "conversations": { "conversation-id": "student-id" },
  "permissions": { "permission-id": "student-id" },
  "supportTickets": { "ticket-id": "student-id" }
}
```

قبل استخدام `--apply`، تؤخذ نسخة كاملة بأداة `scripts/backup.mjs`، وتُحفظ في موقع آمن، وتُجرب استعادتها في قاعدة معزولة. ثم يُشغل فحص الترحيل على القاعدة المستعادة وتُراجع الحسابات والربط والسجلات. يجب جدولة نافذة صيانة لأن التطبيق يقفل الجداول المتأثرة أثناء المعاملة.

```powershell
# خزّن مفتاحًا عشوائيًا من 32 بايت بصيغة hex في متغير البيئة
# STUDENT_TRANSFER_BACKUP_KEY، عبر مخزن أسرار، دون إدراجه في سجل الأوامر أو المستودع.
node scripts/transfer-parent-data.mjs --mapping transfer-mapping.json --apply --backup D:\secure-backups\student-transfer.enc
```

يتطلب التطبيق مفتاحًا صالحًا ومسار ملف جديد. ينشئ لقطة AES-256-GCM لكل البيانات التي سيغيّرها، مع المحادثات ورسائلها وتذاكر الدعم وجلسات ولي الأمر، ثم يعيد قراءتها وفكها ومقارنتها قبل أول كتابة. لا يكتب فوق ملف موجود. لا تحتوي اللقطة المشفرة على المفتاح؛ يُحفظ منفصلًا. هذه لقطة للبيانات المتأثرة، وليست بديلًا للنسخة الكاملة.

يمكن التحقق من اللقطة لاحقًا باستخدام `node scripts/verify-student-transfer-backup.mjs --backup <file>` مع المفتاح نفسه في البيئة. تفك الأداة التشفير وتتحقق من سلامة اللقطة وتعرض الأعداد فقط، دون كتابة إلى قاعدة البيانات أو كشف محتوى السجلات. تختبر الاختبارات رفض المفتاح الخطأ والملف المتلاعب به.

تُنفذ الكتابات في معاملة `Serializable` بقفل يمنع ترحيلين متزامنين. يسجل سجل النشاط وجهة كل سجل مرحّل ويرفض تحويله لاحقًا إلى طالب مختلف. تبقى الحسابات والملفات والإشعارات الأصلية لولي الأمر دون حذف، مع تعطيل الحسابات وإلغاء جلساتها. تُنسخ الإشعارات بمعرفات حتمية ويُحفظ تاريخها وحالة قراءتها، وتُمنع إعادة إرسالها كتنبيهات دفع جديدة. تُنقل أذونات الغياب وملكية تذاكر الدعم إلى الطالب مع إبقاء مؤلفي الرسائل الأصليين. تُضاف عضوية الطالب للمحادثة دون صلاحيات إشراف ويُنهي النظام عضوية الحساب المتقاعد حتى تعمل فحوص التواصل المستقبلية. تُحوّل الإعلانات المستهدفة لولي الأمر إلى الطالب.

إذا لم يكن للطالب حساب، يُنشأ له حساب مستقل باسم `student-<student-id>` وكلمة مرور عشوائية لا تُعرض ولا تُشارك. تعيد الإدارة تعيين كلمة المرور عبر أدوات حسابات الطلاب. لا يُعاد استخدام هوية ولي الأمر أو كلمة مروره. تُنسخ بيانات جهة الاتصال الناقصة إلى حقول الطالب مع إبقاء الأصل.

يؤدي فشل الربط أو التحقق أو النسخ الاحتياطي أو أي كتابة إلى إلغاء المعاملة. عند فشل العملية بعد إنشاء اللقطة، تُحتفظ باللقطة للتحقيق ويُستخدم مسار جديد للمحاولة التالية. بعد النجاح، تُراجع أعداد الإشعارات والعضويات والأذونات والتذاكر وحسابات الطلاب في القاعدة المستعادة أولًا، ثم تُكرر المراجعة بعد تطبيق الإنتاج. لا يتضمن هذا العمل خطوة حذف الأرشيف.
