# واجهة عبدالله بن عمر — 4 نوفمبر 2026

هذه التعديلات محلية فوق التعديلات السابقة، ولم تُنشر أو تُطبّق ترحيلات قاعدة البيانات على أي خادم.

## مراجعة التصميم

افتح [المعاينة البصرية](UI_UX_PREVIEW.html) في متصفح محلي. تعرض سبع شاشات، وتبديل النهاري والليلي، وتخطيطًا يتكيف مع عرض الشاشة. تستخدم ملف `frontend/src/styles/premium.css` المشترك وخط Tajawal المحلي.

المعاينة ثابتة ببيانات تجريبية، وليست اختبارًا للتطبيق المتصل بالخادم. مرجع الفيديو نفسه غير مرفق؛ استُخدمت تفاصيل الحركة المكتوبة في الطلب، ولا توجد مطالبة بمطابقة فيديو لم تتم مشاهدته.

## ما أُضيف

- ألوان وخط ومسافات ومكونات وحالات تركيز موحّدة عبر الصفحات التي تستخدم المكونات الحالية، مع احترام تقليل الحركة.
- تسجيل دخول بحقول كبسولية وأيقونات تتحرك عند التركيز، وتوزيع من عمودين على الكمبيوتر. بقيت المصادقة وحقولها وخياراتها وروابط الدعم والتبرع كما هي.
- ملخص «يومي» حسب الدور وآخر التنبيهات الفعلية في الرئيسية وملف الطالب.
- بطاقات منشورات مشتركة: إعجاب مزدوج، مشاركة رابط، تعديل المنشور والتعليق بواسطة صاحبهما، تأكيد حذف، حالات إرسال وتعليقات. صلاحية حذف المنشور لصاحبه فقط، على الخادم وفي المزامنة المحلية.
- تعديل النصوص المحفوظة دون اتصال يمر عبر طابور المزامنة الحالي، مع إعادة التحقق من الملكية على الخادم.
- أعداد فعلية للحلقات النشطة والطلاب النشطين والمعلمين النشطين في صفحة المدرسة، وروابط التعريف والتعديل المسموح للإدارة.
- حلقات ستوري خضراء وذهبية وتمييز المشاهدة؛ رد نصي خاص يحفظ سياق الستوري ويستخدم سياسة الاتصال الحالية. بقيت الردود القديمة محفوظة ومسارات قراءتها قائمة.
- إخفاء النشاط وآخر ظهور على الخادم، بما يشمل استجابات المحادثات وبيانات اتصال Socket.IO. آخر ظهور يُسجّل من تفاعل التطبيق الظاهر، لا من آخر رسالة، وتُعد الجلسة خاملة بعد 90 ثانية من آخر نشاط مسجل.
- خطط حفظ متعددة في ملف الطالب وملفه الإداري: أسبوعية أو شهرية أو حسب الهدف؛ آيات وصفحات وسور وأجزاء ومهام؛ حلقات تقدم؛ سجل إنجاز؛ تعديل وأرشفة واستعادة. الإنشاء والاعتماد للإدارة والمشرف والمعلم المسؤول وفق صلاحيات الطالب الحالية. قفل الصف ومعرّف طلب ثابت يمنعان احتساب إعادة إرسال الإنجاز مرتين.
- تصنيف الإشعارات حسب النوع، مع تطبيق الفلترة على الخادم وعلى النسخة المحلية.

## قاعدة البيانات

الترحيلات الجديدة إضافية ولا تحذف بيانات قائمة:

1. `20261104010000_user_activity_privacy`: جدول خصوصية النشاط وآخر ظهور.
2. `20261104011000_memorization_plans`: جدول الخطط وسجل الإنجاز، مع مفاتيح خارجية وحدود للإنجاز والهدف.

على بيئة تجريبية مهيّأة، وبعد مراجعة الترحيلات السابقة الموجودة في المشروع وأخذ النسخة الاحتياطية المعتادة:

```powershell
npm --prefix backend run prisma:generate
npm --prefix backend run prisma:deploy
npm --prefix backend run test:ui-domain
npm run build
```

عند عدم تطبيق ترحيل النشاط تفشل قراءة الخصوصية باتجاه الإخفاء. لا يدّعي التطبيق حفظ إعداد الخصوصية أو الخطة إذا رفض الخادم العملية. قراءة الخطط المفتوحة سابقًا تستفيد من كاش API الحالي؛ إنشاء الخطط وتسجيل تقدمها والرد الخاص على الستوري تتطلب اتصالًا. تبقى وظائف المزامنة القائمة محفوظة.

## التحقق وحدوده

- نجح فحص TypeScript للواجهة والخادم باستخدام واجهة TypeScript البرمجية من بيئة JavaScript المتاحة، دون تغيير إعدادات المشروع.
- نجحت 13 حالة جديدة للخصوصية والملكية وصلاحيات الخطط والتكرار، و23 حالة انحدار للمحادثات والإشعارات والأمان. نُفّذت دوال الاختبارات وتسلسلات التأكيد داخل العملية بسبب تعطل تشغيل العمليات الفرعية؛ لم يُدعَ نجاح مشغّل `node --test` نفسه.
- جرى تحليل CSS بواسطة PostCSS وفحص فروق الملفات بحثًا عن أخطاء المسافات.
- لم ينجح بناء Vite: محرك esbuild لا يستجيب في هذه البيئة. لم تُشغّل ثنائيات Prisma ولم تُختبر الترحيلات على قاعدة بيانات فعلية.
- اتصال المتصفح الآلي غير متاح؛ لذلك ما زالت مراجعة التطبيق الحي على الهاتف والتابلت والكمبيوتر، وفحص لوحة المفاتيح وRTL والنهاري والليلي، مطلوبة في بيئة تشغيل سليمة قبل النشر.

لم تُستبدل التعديلات السابقة الخاصة بنقل بيانات ولي الأمر أو النظام المؤسس أو العمل دون اتصال، ولم يُنفّذ نقل إضافي على بيانات فعلية.
